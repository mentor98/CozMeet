                         🔧 TECHNICAL DETAILS
================================================================================

Database Schema (9 Tables):

profiles
├─ id (UUID primary key)
├─ username (unique)
├─ display_name
├─ bio (optional)
├─ avatar_url (Cloud storage)
├─ cover_url (Cloud storage)
├─ posts_count
├─ followers_count
├─ following_count

posts
├─ id (UUID)
├─ user_id (Foreign key → profiles)
├─ caption (text)
├─ image_url (Cloud storage)
├─ visibility (public/private)
├─ created_at
└─ updated_at

post_likes
├─ id (UUID)
├─ post_id (Foreign key)
├─ user_id (Foreign key)
└─ created_at

comments
├─ id (UUID)
├─ post_id (Foreign key)
├─ user_id (Foreign key)
├─ content (text)
├─ parent_comment_id (optional)
├─ created_at
└─ updated_at

follows
├─ id (UUID)
├─ follower_id (Foreign key)
├─ following_id (Foreign key)
└─ created_at

(+ post_saves, post_shares, notifications, shortcuts)

Data Access Pattern:
1. User authenticates with Supabase Auth
2. JWT token obtained
3. Token sent with every request
4. RLS policies evaluate token
5. Only appropriate data returned
6. Images served from CDN
